# C23 — the front end against the standard

`crefactor/cc` is a fork of modernc.org/cc/v4 v4.29.7, a C11 parser with
GNU's extensions; whim's texts are C23 (`nullptr`, `bool`, `usize`, `enum :
long`, `[[fallthrough]]`). This is what C23 the fork, `crefactor/cemit`'s
canonical print and C-lisp (`crefactor/clisp`) handle, how that is measured,
and what stays out.

## The authority

The standard is **ISO/IEC 9899:2024**, "C23". ISO sells it; WG14 publishes
its working drafts free:

- **N3096** (April 2023), the draft that went to ballot;
- **N3220** (February 2024), C23 with the editorial fixes since, the first
  working draft for the next revision. Section numbers here are N3220's.

The practical oracle is **gcc 15.2**, `gcc -std=c23`, which implements every
language feature below (gcc 15 also defaults to `-std=gnu23`). Where the two
could disagree the test asks gcc, since gcc is what compiles whim's product.

## The conformance test

`crefactor/c23conf` (`cd crefactor && go test -v -run TestC23 ./c23conf`
prints the table and the score). A package of its own because it judges
three packages together -- the parser, cemit, and C-lisp, which imports
cemit, so no one of them could hold the test -- and because its files then
feed the other walks of the module: `ccwalk`'s and cemit's walk tests glob
`../*/testdata/*.c`, so every C23 feature here is also a parse those hold
their generated walks to (they caught three node types the walks had not been
regenerated for).

**One small file per language feature**, `testdata/NAME.c`, its first line
the N3220 subclause. 49 files; nothing of the preprocessor (`#embed`,
`__has_include`, `#elifdef`, `#warning`, `__VA_OPT__`), since whim's texts
have no directive but `#include` and cemit refuses any other.

**How it judges**, each file in order, the first no its answer:

1. **gcc accepts it**, `gcc -std=c23 -fsyntax-only`, judged by the status:
   a file gcc refuses is the test's own fault and fails the test outright.
2. **The parser parses it** (`cemit.Parse`: crefactor/cc's `Parse`, as every
   tool here calls it).
3. **cemit prints it, and gcc accepts the print.**
4. **The print is a fixed point**: cemit of it is the same bytes.
5. **The print is the same program**, by two judges. *Tokens*: the original
   and the print split into preprocessing tokens (6.4, by the test's own
   lexer, written from the standard and not shared with the front end it
   judges: it knows `u8'a'`, `1'000'000`, `::`), compared one for one. The
   files are written in the tokens cemit prints -- braces on every body, an
   enumerator list's trailing comma where cemit writes one -- so any token
   that differs is a change of program, a dropped attribute or a respelled
   constant as much as a moved value. One rewrite is allowed and said: a `;`
   right after a `:` is not compared, since C23 lets a label stand before a
   declaration or a `}` and says such a label is as if followed by a null
   statement, which cemit prints (it is the spelling every C accepts, and
   whim's texts are in it); a `;` after any other `:` -- a conditional's, a
   bit-field's, an asm operand list's -- cannot occur. *Objects*: both texts
   compiled with the one compile line's code generation, `gcc -std=c23 -O0
   -fno-stack-protector -c`, under the same base name in two directories, and
   compared byte for byte. With equal tokens equal objects follow; the second
   judge is there for the first one's lexer, and it is the one that sees a
   changed value whatever the spelling.
6. **C-lisp round trips it**: `ToC(ToLisp(file))` is cemit's print byte for
   byte, and the print's forms are the file's forms.

Beside the six, `cc.Translate` type-checks each file and the table reports
what it says without judging it, but **a panic fails the test**: the checker
must not crash on any C23 it is handed.

**Expected failures** are a map in `conf_test.go`, each with its reason; a
listed file that passes fails the test, so the list is never stale. It is
empty: every file passes.

**The control** (`TestControl`): four wrong prints of right ones, each
accepted by gcc -- `[[fallthrough]];` printed `;`, `1'000'000` printed
`1000000`, `0b1010` printed `0b1011`, `- -a` printed `--a` -- and the judge
must refuse each, the tokens judge every one, the object judge the two that
move code and not the two that do not. And a respacing it must take.

## What was added

In the front end (`crefactor/cc`: `c23.go`, and hooks in upstream's files
marked `go-whim`; `crefactor/cc/README.md` is the delta):

- **`[[...]]` attributes in every position**, held in the tree: in the node
  GNU's `__attribute__((...))` is, wherever upstream takes a GNU list, and
  where it takes none -- after a declarator's identifier, between `enum` and
  its tag, after an enumerator, after a function definition's declarator,
  before any statement. A `gnu::` prefix is held apart; another vendor's
  arguments are kept as their tokens. Where upstream parses a GNU list and
  discards it, `[[` stays a syntax error, never a silent drop.
- **`constexpr`**, a storage-class specifier.
- **`_BitInt(N)`**, a type specifier.
- **`typeof_unqual`**, and `typeof(const int)`, which upstream refused.
- **`static_assert(E);`**, and a block's assertion owning its `;`.
- **Digit separators** in the scanner's pp-numbers, read through by the
  checker.
- **`u8'a'`**, of type unsigned char.
- **Storage classes in a compound literal.**
- And a GNU fault found on the way: an attribute list of three values lost
  its second (`__attribute__((cold, noinline, unused))` printed `cold,
  unused`; none such is in whim's input).

In **cemit**, a canonical spelling for each: an identifier's attributes after
it (`x [[maybe_unused]]`), an enum's after `enum`, an enumerator's after its
name, a definition's on its declarator's line, a statement's on a line of
their own above it (and `else` does not chain an `if` that has them), a
member's leading ones (GNU's were printed as nothing before), `_BitInt(N)`,
a compound literal's storage classes before its type.

In **C-lisp** (`SPEC.md`, the C beside each): `(std-attr ...)` for `[[...]]`
(`(std-attr (nodiscard "why") gnu::packed)`), `(name-attr T ATTR...)` for the
attributes after an identifier, `(enum TAG (@ ATTR...) ...)`, `(NAME ATTR...
VALUE)` for an enumerator, `(stmt-attr ATTR...)` before a statement and
`(block (@ ATTR...) ...)`, a definition's attributes after its type,
`(_BitInt N)`, `(typeof_unqual E)` and `(typeof_unqual-type T)`, `(literal
STORAGE... T ITEM...)`, `(static_assert E)`; and the reader takes a `'` in a
number as a separator, not a quote.

## The type checker

`cc.Translate` panics on none of the 49. What it says, as the table prints
it: `constexpr` is read as no storage class -- the object is not made const,
its value not a constant expression to the checker, which still accepts
`constexpr int N = 4; int a[N];`; **`_BitInt` is an error**, *a bit-precise
integer type is parsed, not type-checked*: cc's type system has no
bit-precise kind, and giving it one (sizes, promotions, the usual arithmetic
conversions, `wb` constants) is work in the checker beyond a fork's hooks,
not a parse; `typeof_unqual` drops the qualifiers; separators and `u8` are
read through. Two errors are upstream's and unrelated: `typeof(int *)` is
*TODO ... TypeSpecifierTypeofType* (so `typeof.c` and `typeof_unqual.c`
report it), and a VLA's `= {}` is refused (`empty_init.c`). The pipeline
type-checks nothing: the sweep and the print parse.

## whim's pipeline, and `[[fallthrough]]`

Holding the attributes moved whim's texts, and the pipeline now carries
them. Phase 0's part 0c respells the input's 37
`__attribute__((fallthrough));` `[[fallthrough]];`, and the canonical print
after the seed wrote them `;` -- because the parser discarded them. Every
boundary from q000 on had `;` there, and the phases were written against
it: with the attributes held, q000 differs in exactly those 37 lines and
phase 2 (`nomouse`: *getcmdline_int()'s click and drag -- expected 1,
matched 0*) refuses. At 27b8e77 the old form was kept by name, an option of
cemit's (`NullAttributeStatements`, passed through `crefactor/pipeline`'s
`Config.Print`), so that this change could be made on its own. It is made
now, and the decisions are these.

- **The print is faithful, and has no option.** cemit prints an attribute
  statement as it is written. The option, `cemit.Options` and
  `pipeline.Config.Print` are deleted: nothing asked for the old form, and
  a form no caller asks for is a way to lose an attribute again.
  `TestAttributeStatements` holds C23's, GNU's and a statement's own
  attributes in the print.
- **The phases match what is there.** Four programs matched the `;`:
  `nomouse` (phase 2), `nobuflist` and `nocomplkeys` (phase 3) and part 5a
  (`do_pending_operator()`'s `OP_FILTER` case and `nv_g_cmd()`'s `q`/`w`).
  They match `[[fallthrough]];`; nothing else moved. The in-order build
  found them, one refusal at a time, and then ran to the end.
- **A fallthrough that precedes no case label goes in the sweep.** It
  attaches to nothing else, so it is a statement nothing needs, as a local
  nothing reads is: `crefactor/sweep`'s `fallthrough.go` cuts, in every
  live function, an attribute statement whose attributes are all
  `fallthrough` (C23's or GNU's) where control goes next to no case or
  default label -- the next item of its block, or, at the block's end,
  wherever control goes after the statement the block belongs to: an if's
  branch, a do-while's body, a label's statement, a nested block lead on;
  the end of a switch's, a while's or a for's body and of the function do
  not. That is gcc's own test (*attribute 'fallthrough' not preceding a
  case label or default label*), measured on gcc 15: a fallthrough at the
  end of an if's branch or of a `do { } while (0)` before a case label is
  accepted, one before a statement or a `}` that ends the switch is not.
  `TestPruneOrphanedFallthrough` holds the rule with gcc `-Werror` as its
  judge. The rule is one place and not 37 special cases, and on whim's
  pipeline it **cuts nothing**: every cut that leaves a fallthrough
  without its next case takes the fallthrough with it, and no boundary
  has one (none warns). It is there for the cut that would.
- **Where the 37 went.** Of the 37 at q000, 17 go with the code around them
  -- phase 1 3 (`command_line_scan`), phase 2 1 (getcmdline_int()'s click
  and drag), phase 3 11 (the NFA engine's 5 in `addstate` and
  `nfa_regatom`, `quote_meta`'s 3, `set_context_by_cmdname`'s,
  `set_ctrl_x_mode`'s and one of `edit`'s), phase 5 2 (part 5a's two
  cases) -- and **20 reach the product**, in `edit` (3), `nv_zet` (7),
  `regatom` (3), `nv_g_cmd` (2), `do_more_prompt`, `findmatchlimit`,
  `getcmdline_int`, `ins_start_select` and `nv_edit`. The counts by
  boundary: 37, 34, 33, 22, 22, then 20 from q005 on.

What it measured:

- the product differs from the one before in exactly 20 lines, each `;`
  become `[[fallthrough]];`, and so does every boundary (only such lines,
  as many as it holds), the line counts unchanged; `go tool whim measure`
  gives every row of `internal/phase/boundaries.md` back, binaries included;
- `bin/whim-vim` is byte-identical (775,016 bytes): an attribute emits no
  code at -O0;
- gcc's `-Wimplicit-fallthrough` (added only to measure; it needs `-c`,
  `-fsyntax-only` does not see it) on the product: **18 warnings before, 0
  after** -- the other 2 of the 20 bare `;` follow a case label with no
  statement (`case ESC:` and `case Ctrl_P:`, the two 0c's account names),
  where gcc has nothing to say; on the boundaries 37, 34, 33, 21, 20 and 18 from q005 before, 0 on
  every one after; without the flag, no boundary warns either side;
- every generated editor -- `editor/editor.go`, `braaam/editor/`,
  `editor.clj`, `Editor.hs` and its parts, `editor.rs`, `editor.ss` -- is
  byte for byte what it was: each backend reads an attribute statement as
  the null statement it is, and a fall into the next case was already the
  structure togo writes.

## What stays out

- **The preprocessor's C23** -- `#embed`, `__has_include`,
  `__has_c_attribute`, `#elifdef`, `#elifndef`, `#warning`, `__VA_OPT__`:
  the test has no directive, since cemit refuses every one but `#include`.
- **`_BitInt` in the type checker**, above.
- **`[[...]]` where upstream parses GNU's attributes and throws them away**
  -- just inside a declarator's parenthesis, `int ([[a]] *p)`, and before an
  abstract declarator -- refused with its position rather than dropped.
- **C11's `u'x'`, `U'x'`, `u"x"`, `U"x"`**: not C23's change, and refused as
  before (the scanner reads `u` as an identifier). `u8` is the one added.
- **`_Static_assert(E)` keeps its old spelling** only up to the print:
  cemit writes every static assertion `static_assert`, the C23 keyword, a
  canonical respelling the files avoid.
- **GNU's attributes just after a label**, `case 1:
  __attribute__((fallthrough));`, are read as the label's, which upstream
  parses and discards, so the print writes `;` there; after a statement, GNU's
  attribute statement is held. whim's input has none -- each of its 37
  follows a statement, so the seed's print holds them, and 0c respells them
  after it; the two that come to follow a label bare later are C23's by then.
- A C23 attribute statement at file scope, `[[]];`, parses and prints, but
  no file holds it to a judge: it declares nothing.
