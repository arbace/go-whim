# How the transpiled editor could be more idiomatic Go: a survey

**Since written:** its first recommendation is done -- `make whim-test` now runs
the 44 cases on the Go editor against the C product, with the control, on every
run (the finding below that it never did is the state it was written in). Its
second is done too: items 1 and 2 (lint) are 0 on vet, staticcheck and `gofmt
-s`, by generator rules and phases 164-165. Chasing them found a generator bug the
survey did not: a comma expression whose value is a constant lost its effects,
which silenced 28 of the regexp compiler's error exits in the Go. The third
(truth values typed `bool`) is phase 166, and item 4 (locals where C declares them)
is the generator's now. Item 7 is done in the part that is a
rule: a pointer into an array that never walks is a plain `*T` (`&a[i]`,
`p.Ref(k)`), unless it is also handed on as a `void *`, which may walk it
unseen. That took the `Ptr` of another element type than `byte` from 320 to
149, `Ptr[Ptr[byte]]` from 107 to 12, `Addr(` from 108 to 9 and `.P()` from
462 to 86. The rest of it -- a forward-walking pointer as a resliced `[]T` --
is not done: `Ptr[byte]` is C's string, compared and subtracted across the
file, and one class. Item 10 is phase 168: a `goto` whose label marks
`return x` is that return, 19 of them, and seven functions with no `goto` left
have their locals where C declares them. Items 11 and 12 are declined,
measured on `editor/` as it stands after phase 168 (a throwaway `go/types`
counter):

- **11, the globals as an `Editor` struct.** It is mechanical, but it is not
  readable: `editor.go` names its 854 package variables 14,720 times on
  11,795 of its 57,554 lines, and calls its functions 11,560 times; every one
  would become `e.x` or `e.f(...)`, a fifth of the file rewritten to say the
  same thing, and the line-for-line match with `editor.c` that
  `CONVENTIONS.md` keeps would go with it. What it buys is several editors in
  one process, which neither the host nor the C core has any use for: the C is
  one editor per process too, and the Go follows the C.
- **12, `package editor` and a `Host` interface.** The seam is small: the core
  calls 16 host functions at 33 sites, plus `vim_snprintf` at 174, and the host
  names 19 of the core's names -- all but `vim_main` and `deathtrap` from
  `vim_snprintf`'s formatter, which is vim's code living in `host.go` only
  because the generator refuses a variadic function. But a package split makes
  every name that crosses it exported, so the generator would need a name map
  for the host calls and wrappers for `vim_main` and `deathtrap`, and what the
  survey says it unlocks -- in-process tests with a fake host -- does not
  follow without item 11: the globals are set once by `init()`, and
  `host_exit` ends the process, so a test binary could run one session. The
  suite already runs the Go editor as a process against the C
  (`whim test`), which is the check this would have provided. Splitting
  `editor.go` into files is cosmetic, as the survey says.

The throwaway instruments it names under `.tmp/idiom/` were not kept.

2026-09-24. A read-only survey: no tracked file changed, nothing committed, and
no `whim build` was run. It covers `editor/editor.go` as tracked at `de80df5`
(59,426 lines, generated by `internal/gen`), plus the hand-written
`editor/crt.go` (274 lines) and `editor/host.go` (1,704 lines).

**A finding about verification, which comes before everything else.**
`make whim-test` (`internal/suite.Check`) builds its reference **and** its
candidate from C with gcc. It never runs the Go editor, so it cannot verify a
change to `editor/`. `whim-editor-check` only checks that `editor.go` is what
`internal/gen` writes, and says nothing about behaviour. The suite's own parts
do work on the Go binary. `gocmp` calls `suite.Compare(cases, cRef, goBinary)`:

- **the Go editor answers all 44 cases byte-for-byte the same as the C product**;
- a Go control, `" INSERT"` changed to `" INSERX"` in a copy of `editor.go`,
  **differs in 41 of the 44**, so the check can fail.

That comparison is the verification recipe for every item below.

Note: `internal/suite/suite.go` has uncommitted edits in this checkout, and
`gocmp` ran against them.

## The patterns

Each item gives what the pattern is, where the fix belongs, and its cost and
risk. "Generator" means `internal/gen`, applied mechanically, which rewrites
`editor.go` everywhere at once. "C phase" means a new pipeline phase that removes
the C shape, which improves `whim-vim.c` and the Go together. "Hand" means a
change to `crt.go`/`host.go`, or to the Go after generation.

### 1. Lint debris in the generated output (vet/staticcheck/gofmt -s)

| Finding | Count | Example | Cause |
| --- | --- | --- | --- |
| `true`/`false` spelled `(1 != 0)`/`(0 != 0)` | 80 + 28 | `editor.go:6248` `curbuf.b_modified_was_set = (0 != 0)` (C: `= false;`) | `truth()` in `body.go:290` applied to a constant |
| `*&x = T{}` (SA4001) | 22 | `editor.go:7539` `*&buf.b_chartab = [32]byte{}` | the zero-`memset` rule at `body_expr.go:1020` writes `*` + `&expr` |
| `!(!p.Nil())` (SA4013) | 5 | `editor.go:22794` | the loop-condition-as-`break` rule negates a negation |
| redundant composite types (`gofmt -s`) | 112 lines | `[194]S_nv_cmd{S_nv_cmd{…}, …}` at `editor.go:4502`, which is one 16,227-character line | the initializer emitter; 308 lines are over 200 columns |
| `var x T` then `x = e` on the next line (S1021) | 129 flagged | `musl_strlen`: `var a Ptr[byte]` / `a = s` | locals are hoisted (item 4) |
| unused type aliases (U1000) | 46 | `__builtin_va_list`, `__predefined_size_t`, `ex_func_T`, … | every typedef is emitted |
| identical operands (SA4000) | 31 | `pat.length = (1 - 1)` at `editor.go:14498` | constant-folded C (`sizeof("") - 1`) and the bool constants above |
| redundant `break` (S1023, SA4011) | 7 + 2 | `editor.go:11751` | a C `break` at the end of a case |
| empty branch (SA9003) | 4 | `editor.go:11508` | C's `if (x) ;` |

- **Where:** the generator, in each case a local rule: fold `!(!x)`, strip `*&`, emit
  `true`/`false`, elide the element types in composite literals, and skip
  unreferenced aliases.
- **Cost:** small. One sitting per rule.
- **Risk:** none behaviourally. Each is a textual identity the compiler checks.
- **Verify:** `go build ./editor`, then the `gocmp` comparison, then
  `whim-editor-check` after committing the regenerated file.

### 2. Unreachable and dead statements that the C carries too

- **The pattern:** vet finds 32 × *unreachable code*. They are in the C as well.
  `whim-vim.c:6482` `return del_chars(1L, fixpos); return del_bytes(1L, fixpos, TRUE);`
  is `del_char()` at `editor.go:7064`. `vim_islower`/`vim_isupper`/`vim_toupper`
  (`editor.go:8331–8388`) return before a Latin-1 branch that has no way in any
  more.
- **Related:** staticcheck finds 2 allocation-failure checks that phases 148/149
  missed (SA4031: `mp = new(S_mapblock); if mp == nil`, `editor.go:23692`;
  `frp`, `editor.go:58567`), 6 values never used (SA4006), 1 overwritten
  argument (SA4009) and 1 discarded call result (SA4017).
- **Where:** a C phase (*statements after a `return`/`goto`/`break` go*; *the
  last two `== NULL` tests of a fresh allocation go*), so the C loses them too.
  The generator could drop statements after a terminator instead, but then the
  C and the Go would disagree about the same code.
- **Cost:** small.
- **Risk:** none. It is dead code by definition, and `whim-build-check` plus
  `whim-test` would guard the C side.

### 3. C-style truth values: `int32` for bool and for OK/FAIL

- **The pattern:**
  - 565 functions return `int32`. **133 return only `TRUE`/`FALSE`/`B2i(…)`** and
    **65 return only `OK`/`FAIL`**.
  - Of the 463 call sites of the 133 boolean functions, 393 compare the result
    `==`/`!= 0`, 23 assign it, 25 discard it, 20 return it and 2 pass it on.
  - Of the 202 call sites of the 65 status functions, 83 compare it with
    `OK`/`FAIL`, **83 discard it**, 21 assign it and 15 return it.
  - Across the file: `B2i` 361, `TRUE` 1,198, `FALSE` 1,342, `x != 0` 3,065,
    `x == 0` 1,710, and `B2i(…) ==/!= 0` 8.
- **Where:** best as a C phase that retypes these functions (and the `int`
  flags they flow into) as C23 `bool`. The C already uses `bool` in 40 places,
  and the generator already maps `cc.Bool` to Go `bool` (`gen.go:68`); 275
  `bool`s reach the Go today. The generator could do the same through a flow
  analysis like its pointer union-find (a value only ever `0`/`1`, only tested
  for truth). OK/FAIL should become `bool` (`ok`), not `error`, because FAIL
  carries no information: the message has already gone through `emsg`.
- **Cost:** medium to high. Inference is needed where a "flag" also holds `-1`
  or `2`: `nv_cmds.cmd_arg` holds `TRUE`, `FORWARD` and `-1`.
- **Risk:** low if the analysis refuses mixed values.
- **Verify:** `whim-build-check`/`whim-test` for the C, `gocmp` for the Go.

### 4. Locals hoisted to the top of the function, and generator temporaries

- **The pattern:**
  - The generator hoists every local to the top of its function (`body_stmt.go:70`),
    so that Go's `goto` never jumps over a declaration. That is **4,632 locals
    in 935 functions**.
  - Only 41 functions contain a `goto`. **3,914 hoisted locals are in the 894
    functions that have none.**
  - A further 971 temporaries (`var tN`, from `?:` and split side effects) are
    also declared at the top. `musl_abs` is 9 lines for `if a > 0 { return a }; return -a`.
- **Where:** the generator. In a function with no `goto`, declare each local in
  the scope C declares it, as `x := e` when it has an initializer, and declare
  temporaries just before their `if`.
- **Cost:** medium: scoping and name collisions.
- **Risk:** one real one. A C local declared *without* an initializer inside a
  loop, and read before it is written on a later iteration, keeps its old value
  in the hoisted Go (as gcc `-O0` does). Moved into the loop body, it would be
  zeroed each time. That is UB in C, but it is observable. Keep such locals
  hoisted (the analysis is "definitely assigned before read"), or prove that
  none exist with gcc `-Wmaybe-uninitialized`.
- **Verify:** `gocmp`.

### 5. Hand-transpiled libc: `musl_*`

- **The pattern:** 29 musl functions are transpiled byte by byte:
  `musl_strlen` (129 calls), `strcmp` (58), `strncmp` (83), `strcpy` (53),
  `is*`/`to*`, `strtol` and others.
- **Where:** the generator's replacement table. It already maps 11 C functions
  to `crt.go`; this would add Go implementations in `crt.go` (for example
  `bytes.IndexByte` for `strlen`).
- **Cost:** small.
- **Risk:** low.
- **Verify:** a Go fuzz test of each replacement against the transpiled
  original, then `gocmp`.

### 6. Key codes as arithmetic

- **The pattern:** 394 key codes are written out as expressions, such as
  `-('K' + (65 << 8))` and `-(KS_EXTRA + (76 << 8))`, and 97 `case` labels are
  among them (`editor.go:11753`, the `nv_cmds` table). They are vim's
  `TERMCAP2KEY` macros, whose names went when the preprocessor was removed.
- **Where:** a C phase that names them as enum constants (`K_KENTER`, …), or a
  table in the generator. The C phase serves both products.
- **Cost:** small to medium.
- **Risk:** none. The values are the same, so the compiler's constant folding
  is the proof, and `whim-build-check` holds for the C.

### 7. `Ptr[T]`: the C pointer that walks

- **The pattern:**
  - `Ptr[` appears 2,928 times, and 1,458 parameters and locals are typed `Ptr`.
  - The method calls: `.Set` 2,754, `.Add` 1,616, `.Get` 1,350, `.At` 1,235,
    `.Nil` 636, `.Ref` 464, `.P` 462, `.Put` 175, `.Sub` 164, `Lt`/`Le`/`Gt`/`Ge` 70.
  - **2,105 of the 2,223 `int32→int` conversions are `Ptr` index arguments**
    (`.At(int(i))`).
  - Where the program really needs a C pointer: 96 `Ptr == Ptr`, 164 `Sub`,
    70 orderings and 114 `Add(-k)`.
- **`unsafe` and `uintptr`:** these appear only in `crt.go` (`unsafe.Slice`,
  plus a `uintptr` difference in `Sub` for two views of one array) and in
  `host.go` (ioctl and `rt_sigaction`). Instrumented over the 44 cases, **the
  `uintptr` path in `Sub` was taken 0 times**. The corpus is small, so this is
  evidence rather than proof.
- **Where:** the generator's pointer analysis. It could add a third class: a
  pointer that only walks forward and is never compared or subtracted becomes
  a Go `[]T` resliced (`s = s[1:]`). `Ptr` would stay for the rest.
- **Cost:** high.
- **Risk:** medium, because every flow has to be classified correctly.
- **Verify:** `gocmp`, and the panics that `slice()` gives out of range.

### 8. C strings

- **The pattern:**
  - `Ptr[byte]` appears 2,589 times, and there are 1,777 `S("…")` literals.
  - `S()` looks each literal up in a map when it is evaluated. That was
    measured at 85,731 lookups over the 44 sessions (about 1,950 each).
  - `GoString` is used only by the host.
- **Why Go `string` is the wrong target:** vim edits its text in place, so the
  mutable idiom is `[]byte`, which is item 7.
- **Where:**
  - generator: hoist each distinct literal into a package-level `var`. This is
    cheap, and identity is kept because the map already makes it one
    allocation;
  - a full string model: by hand, as a redesign. Out of scope for a mechanical
    pass.

### 9. Integer widths and conversions

- **The pattern:** 7,133 conversions to basic types, only 8 of them redundant.
  The rest are `int32→int` (2,223, item 7), `byte→int32` (2,099, C's char
  promotion, mostly `int32(p.Get())`), `int32↔int64` (844) and `uint64→int`
  (334).
- **Recommendation:** leave these alone. C `int` → Go `int` changes overflow
  from 32-bit to 64-bit wrap-around, and vim has overflow guards written for 32
  bits. The index conversions disappear with item 7, not with a width change.

### 10. `goto`

- **The pattern:**
  - There are 183 `goto`s in 41 functions, and all but 2 go forward.
  - The busiest functions: `getcmdline_int` 33, `do_one_cmd` 19,
    `get_address` 12.
  - The commonest targets: `theend` 44, `skip` 19, `doend` 19,
    `cmdline_not_changed` 16, `error` 13, `fail` 10.
  - 35 labels sit at function level. 9 of them are followed by at most one
    statement (for example `theend: return ret` in `ml_append_int`,
    `ml_delete_int`, `do_join`, `match_keyprotocol` and `do_map`).
- **Where:** a C phase: *a `goto` whose target is `return x` is that `return`*.
  The rest are legal, readable Go cleanup jumps, so there is little value in
  restructuring them.
- **Cost:** small for the 9.
- **Risk:** none. At the `goto`, `return x` returns what the label would.

### 11. Global mutable state

- **The pattern:** 824 package-level `var`s, 102 of them `p_*` options.
  **1,192 of 1,693 functions read a package variable, and 603 assign one**
  (directly, or through a field or element of one). `curwin` appears 2,328
  times and `curbuf` 933 times. One `init()` of 2,521 lines sets the initial
  values.
- **What that costs:** one editor per process, and no in-process tests that
  can run in isolation.
- **Where:** the generator. Mechanically it could make every global a field of
  `type Editor struct` and every function a method, with the receiver threaded
  through. The 180 functions used as values (the `nv_cmds` and ex tables)
  would become method values bound per instance.
- **Cost:** high, though mechanical.
- **Risk:** low behaviourally, with a small speed cost.
- **Depends on:** item 12.

### 12. Package structure

- **The pattern:** `editor/` is `package main`: one 59,426-line file, plus the
  runtime and the host. The core calls the host directly:
  - 16 host functions (`musl_read_input`, `musl_wait_for_input`, `host_write`,
    `host_time`, `musl_now_ms` ×8, …);
  - and vim's own `vim_snprintf` (157 calls). It lives in `host.go` only
    because the generator refuses variadic functions.

  Part II made the C an embeddable core behind a computed interface; the Go
  has no such seam.
- **Where:**
  - generator: emit `package editor`, and route calls to the names defined
    outside `editor.c` (the same computed interface) through a `Host`
    interface value;
  - hand: split `host.go` into a `Host` implementation in `cmd/…` plus `main`,
    and move `vim_snprintf` into the core package.
  - Splitting `editor.go` into files (types, globals, `init`, functions) is
    trivial in the generator but cosmetic.
- **Cost:** medium.
- **Risk:** low.
- **Verify:** `gocmp`.
- **What it unlocks:** in-process tests with a fake host.

### 13. Naming

- **The pattern:** staticcheck ST1003 on the un-headed copy: **4,546 × underscores and
  891 × ALL_CAPS** (plus 133 in `host.go`).
  - Of the names: 1,523 of the 1,694 functions are snake_case and 1,009 of
    the 1,140 constants are ALL_CAPS.
  - 313 identifiers carry a trailing `_` (`len_`, `type_`, `string_`) to avoid
    a Go keyword.
  - 51 structs are called `S_tag`, with 85 aliases (`buf_T = S_file_buffer`).
  - 514 of the 753 struct fields have a C namespace prefix (`b_` 76, `w_` 70,
    `sg_` 17, …).
- **Where:** the generator, through a name map. Renaming, though, gives up the
  line-for-line match with `editor.c` that `CONVENTIONS.md` exists to keep, and
  `host.go` would have to follow.
- **Recommendation:** do it last, if ever. The cheap part is one name per
  struct (drop `S_` where the typedef is unique): 85 aliases fewer.

### 14. Unused parameters and out-parameters

- **Unused parameters:** 130 of 2,814. **42 are in the 180 functions used as
  values**, whose signature is fixed by the table they sit in, and **88 are in
  ordinary functions**, such as `buf_get_fname.buf`, `win_line_start.wp` and
  `home_replace.one`.
  - Where: a C phase (drop the parameter and its argument, where the argument
    has no effects), for both products.
  - Cost: small. Risk: none, where the arguments are pure.
- **Out-parameters:** 154 integer pointer parameters (`*int32`, …) in 110
  functions; `Addr(&x)` 108.
  - Idiomatic Go would return several results, but that needs a
    write-before-read analysis per parameter.
  - Where: the generator or by hand. Cost: medium to high.

### 15. Function size

- **The pattern:** the median function is 13 lines and the 90th percentile 72.
  106 are over 100 lines, 36 over 200 and 7 over 500: `regmatch` 1,030,
  `win_line` 836, `win_update` 680, `ex_substitute` 660, `regatom` 635,
  `do_put` 581, plus `init` 2,521.
- **Where:** by hand, or a C phase.
- **Recommendation:** low value against high risk. Leave it.

### 16. `switch`

- **The pattern:** 70 switches, 599 case labels and 25 `fallthrough`s. The
  translation is already idiomatic apart from the 9 redundant `break`s in
  item 1.
- **Recommendation:** nothing to do.

### 17. Tests

- **The pattern:** there is no `_test.go` in `editor/`, and nothing in the
  repository runs the Go editor's behaviour (see *How it was measured*).
- **Where:** hand. A `go test ./editor` (or a `whim test --go`) that drives
  `internal/suite`'s cases on the Go binary against the C product, with the
  Go control. `gocmp` is about 30 lines.
- **Cost:** small.
- **Risk:** none.

### 18. `crt.go` and `host.go`: small hand fixes

- `GaGrowTo` uses `reflect.MethodByName("GrowTo")` (`crt.go:257`). An interface
  assertion does the same (`interface{ growTo(int) any }`), and `reflect`
  leaves the runtime.
- `host.go`'s formatter uses `reflect` to sort `...any` arguments. A type switch
  over the few types the core passes would do.
- `host_free` is unused (U1000). ST1020/ST1022 are two comment forms.
- `ioctl`/`sigaction` through `syscall` + `unsafe`: `golang.org/x/sys/unix` would
  be the idiom (`IoctlGetTermios`, `IoctlGetWinsize`), at the price of a
  dependency.
- Cost: small. Risk: none. Verify with `gocmp`.

### Recommended first three

1. **A behaviour check on the Go editor.** Wire `suite.Compare(cases,
   cReference, goBinary)` plus a Go control into `whim test` or a
   `go test ./editor`. Measured today: 44/44 identical, and the control seen by
   41. Without it, `make whim-test` verifies only the C, and none of the
   changes below could be checked.
2. **Clean output from the generator, plus one C sweep for dead statements.**
   Emit `true`/`false`, strip `*&`, fold `!(!x)`, elide composite types and
   skip unused aliases in `internal/gen`. Remove the 32 unreachable statements
   and the 2 stale `== nil` checks in C. It is small, cannot change
   behaviour, and takes `go vet`, `staticcheck` (correctness checks) and
   `gofmt -s` to zero.
3. **Truth values as `bool`.** Retype the 133 predicate functions and 65
   OK/FAIL functions, and the flags they flow into, as C23 `bool` in a C phase.
   The generator already maps `bool`. Of the semantic changes, this one
   removes the most C-shaped Go, and both products gain.
